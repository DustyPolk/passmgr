# TODO

Ordered, small, testable tasks. One unchecked item per iteration; split items that
are too big rather than doing partial work.

Rules that apply to every item:
- The agent-facing surface returns references and metadata, never secret values.
- Every security-relevant behavior needs a test that proves it (e.g. the secret is
  absent from stdout, stderr and logs).
- No new network-capable dependency. Justify any new dependency in `PROGRESS.md`.

## Phase 0 — make the existing tool obey the invariants

The current Rust CLI (commit f93b765) prints plaintext unconditionally in `get` and
prints a generated password in `add --generate`. Those are invariant violations and
come first.

- [x] **0.1 `get` becomes metadata-only by default.** `get <service>` prints
      service, username, and a `password: <redacted>` marker (no value). Add
      `--reveal` as the only path to plaintext; for now `--reveal` may still work
      on a TTY. Test: `get` over a pipe prints no password bytes.
- [x] **0.2 Gate `--reveal` on a TTY and on agent mode.** Refuse `--reveal` unless
      stdin *and* stdout are TTYs and no agent marker is set (`PASSMGR_AGENT`,
      `CLAUDECODE`, `CURSOR_AGENT`, `CODEX_SANDBOX`). Refusal happens before the
      vault is opened. No bypass flag. Tests: piped stdin, piped stdout (pty on
      stdin, pipe on stdout), and each agent marker all fail with exit code 5 and
      no secret on stdout/stderr; a real pty reveal still succeeds.
- [ ] **0.3 Stop printing generated secrets.** `add --generate` no longer prints the
      generated password; it prints a confirmation with the entry name only.
      Test: stdout/stderr contain no generated bytes (compare against the value
      read back via `get --reveal` in-process, not via the CLI).
- [ ] **0.4 `--agent` global flag + agent detection module.** `src/agent.rs`
      already decides "is this an agent context" (`agent_marker()`,
      `is_agent_context()`, `check_reveal()`); add the global `--agent` flag and
      make it force the same state, including in `check_reveal` (a flag cannot
      weaken the gate — `--agent` can only *add* refusal). Unit tests for every
      marker and for `--agent` itself.
- [ ] **0.5 Stable exit codes.** 0 ok, 2 usage, 3 not found, 4 auth failed,
      5 refused (non-TTY reveal / agent), 6 malformed vault. `Error::Refused`
      already maps to 5; the remaining variants still exit 1. Document in `--help`
      and assert in tests.
- [ ] **0.6 Add `rm` (alias of `delete`) and `edit <service> [--username U]
      [--generate]`.** Editing the password re-prompts twice. Tests: rename,
      rotate, unknown service.

## Phase 1 — reference model and audit-friendly metadata

- [ ] **1.1 Entry references.** Give each credential a stable random `id` (16 bytes,
      hex) stored in the payload, and a `ref` syntax `pm://<id>` (or
      `pm://<service>#<id-prefix>`). Requires store version 2 with a migration
      reader for version 1 (no data loss, no crypto change); document in
      `FORMAT.md`. Tests: old payload still decodes, ids are unique and stable
      across saves.
- [ ] **1.2 `list --json` and `show <ref>`.** Metadata only: ref, service,
      username, tags, created/rotated timestamps. No values. Test asserts no
      value substring appears.
- [ ] **1.3 Tags** on credentials (`--tag`), used later for grant scope. Test:
      filter by tag, reject unknown/empty tags, `list --tag`.
- [ ] **1.4 `last_rotated` timestamp** per credential, updated by `edit`.
      Store version bump handled in 1.1's migration.

## Phase 2 — unlock daemon (`pmd`)

- [ ] **2.1 Protocol module.** Length-prefixed JSON framing with `version` field and
      a hard max message size (e.g. 64 KiB). Pure functions, no I/O. Tests:
      round-trip, truncated frame, oversized length, bad version, unknown request
      type — all rejected without panic.
- [ ] **2.2 Socket setup.** `$XDG_RUNTIME_DIR/passmgr/pmd.sock` (dir 0700, socket
      0600; macOS per-user 0700 dir fallback). Stale-socket detection, single
      instance lock. Tests where the platform allows.
- [ ] **2.3 Peer credential check.** `SO_PEERCRED` on Linux, `getpeereid` on macOS;
      reject mismatched UID before parsing a request. Test with a helper that
      connects and asserts rejection when the check is forced to fail.
- [ ] **2.4 `pm unlock` / `pm lock`, idle timeout, SIGTERM/SIGINT wipe.** Key held
      only in daemon memory; `mlock` best-effort; `prctl(PR_SET_DUMPABLE, 0)` on
      Linux. Tests: idle timeout fires, `lock` wipes (subsequent request fails),
      signal handler exits cleanly and removes the socket.
- [ ] **2.5 Session token file** (`$XDG_RUNTIME_DIR/passmgr/session`, 0600) written
      at unlock; requests carry it; mismatch rejected. Test: wrong token rejected,
      token file mode is 0600.
- [ ] **2.6 `run --env NAME=<ref> -- <cmd>` via the daemon.** The daemon spawns the
      child, relaying redacted stdout/stderr and the exit code. Tests: child sees
      the variable; the secret appears in neither the socket bytes nor the client's
      output nor the audit log; large output is redacted in chunks (no
      chunk-boundary leak — implement streaming redaction with an overlap window).
- [ ] **2.7 `SECURITY.md` limit note**: same-user process can read
      `/proc/<pid>/environ` while the child runs. Not optional.
