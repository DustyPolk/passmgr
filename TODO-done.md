# Completed TODO phases (archived by loop.sh)

## Phase 0 — make the existing tool obey the invariants

The current Rust CLI (commit f93b765) prints plaintext unconditionally in `get` and
prints a generated password in `add --generate`. Those are invariant violations and
come first.

- [x] **0.1 `get` becomes metadata-only by default.** `get <service>` prints
      service, username, and a `password: <redacted>` marker (no value). Add
      `--reveal` as the only path to plaintext; for now `--reveal` may still work
      on a TTY. Test: `get` over a pipe prints no password bytes.
- [x] **0.2 Gate `--reveal` on a TTY and on agent mode.** Refuse `--reveal` unless
      stdin *and* stdout are TTYs and no agent marker is set (`PASSMGR_AGENT`,
      `CLAUDECODE`, `CURSOR_AGENT`, `CODEX_SANDBOX`). Refusal happens before the
      vault is opened. No bypass flag. Tests: piped stdin, piped stdout (pty on
      stdin, pipe on stdout), and each agent marker all fail with exit code 5 and
      no secret on stdout/stderr; a real pty reveal still succeeds.
- [x] **0.3 Stop printing generated secrets.** `add --generate` no longer prints the
      generated password; it prints a confirmation with the entry name only.
      Test: stdout/stderr contain no generated bytes (compare against the value
      read back via `get --reveal` in-process, not via the CLI).
- [x] **0.4 `--agent` global flag + agent detection module.** `src/agent.rs`
      already decides "is this an agent context" (`agent_marker()`,
      `is_agent_context()`, `check_reveal()`); add the global `--agent` flag and
      make it force the same state, including in `check_reveal` (a flag cannot
      weaken the gate — `--agent` can only *add* refusal). Unit tests for every
      marker and for `--agent` itself.
- [x] **0.5 Stable exit codes.** 0 ok, 2 usage, 3 not found, 4 auth failed,
      5 refused (non-TTY reveal / agent), 6 malformed vault. `Error::Refused`
      already maps to 5; the remaining variants still exit 1. Document in `--help`
      and assert in tests.
- [x] **0.6 Add `rm` (alias of `delete`) and `edit <service> [--username U]
      [--generate]`.** Editing the password re-prompts twice. Tests: rename,
      rotate, unknown service. (Implemented with an additional `--rename NAME`
      flag so a service can be renamed; metadata-only edits skip the password
      prompt.)

## Phase 1 — reference model and audit-friendly metadata

- [x] **1.1 Entry references.** Give each credential a stable random `id` (16 bytes,
      hex) stored in the payload, and a `ref` syntax `pm://<id>`. Requires store
      version 2 with a migration reader for version 1 (no data loss, no crypto
      change); document in `FORMAT.md`. Tests: old payload still decodes, ids are
      unique and stable across saves. (Implemented as `pm://<32 hex>` with full ids
      only: no prefix form, so a reference is never ambiguous. `list` and `get`
      print the reference; renaming preserves it.)
- [x] **1.2a `list --json` and `show <ref>`** with the metadata that exists
      today: `ref`, `service`, `username`. `list --json` prints
      `{"entries":[...]}`; `show [--json] <ref>` resolves a full `pm://`
      reference (references only; bad ref = exit 2, unknown ref = exit 3) and
      prints no password field. New `Error::EntryNotFound` (exit 3),
      `Vault::get_by_ref`, `serde_json` dependency. Tests: JSON parses, values
      round-trip through escaping, reference survives a rename, and the secret
      is absent from stdout/stderr in both text and JSON modes.
- [x] **1.2b Extend the JSON entry with `tags`, `created` and `last_rotated`.**
      Schema addition only (agents must tolerate new keys). Tags now exist
      (1.3), so this was blocked only on 1.4 (`created`/`last_rotated`); all
      three keys were added together. (Tags are a sorted array; timestamps are
      RFC 3339 UTC strings, `null` when the stored value is 0 = unknown. The
      vault still stores raw Unix seconds. `src/timestamp.rs` does the
      conversion with no new dependency.)
- [x] **1.3 Tags** on credentials (`--tag`), used later for grant scope. Test:
      filter by tag, reject unknown/empty tags, `list --tag`. (Store version 3;
      `--tag` on `add`/`edit`, `--clear-tags`, `list --tag` with AND semantics,
      sorted/deduped tags, 1-32 bytes `[a-z0-9._-]`, max 32 per credential.
      Tags are printed as metadata in text output and deliberately kept out of
      JSON until 1.2b.)
- [x] **1.4 `created` / `last_rotated` timestamps** per credential. Store version
      4: each payload entry gains two `u64` Unix seconds fields (`created`,
      `last_rotated`); versions 1-3 migrate with `0` ("unknown"). `add` sets
      both, `set_password` updates only `last_rotated`, values above
      253402300799 are rejected. `created` was added in the same format bump as
      `last_rotated` because 1.2b needs both and two store-version bumps would
      be wasted work. JSON output added them in 1.2b.

## Phase 2 — unlock daemon (`pmd`)

- [x] **2.1 Protocol module.** Length-prefixed JSON framing with `version` field and
      a hard max message size (e.g. 64 KiB). Pure functions, no I/O. Tests:
      round-trip, truncated frame, oversized length, bad version, unknown request
      type — all rejected without panic. (`src/protocol.rs`: `encode`/`decode`,
      streaming `FrameDecoder`, envelope `{"version":1,"request":{"type":...}}`,
      types `ping`/`lock`/`run`, 64 KiB body cap checked before slicing, unknown
      fields tolerated, unknown types/versions rejected, `run.env`/`ref`/`command`
      bounds validated on encode and decode, and no request type can carry or
      return a plaintext value.)
- [x] **2.2 Socket setup.** `$XDG_RUNTIME_DIR/passmgr/pmd.sock` (dir 0700, socket
      0600; macOS per-user 0700 dir fallback). Stale-socket detection, single
      instance lock. Tests where the platform allows. (`src/socket.rs`:
      `RuntimePaths` resolves/validates the 0700 dir, `DaemonSocket::bind`
      takes a non-blocking `flock` on `pmd.lock` before touching the socket,
      and only unlinks a socket after a probe connect gets `ECONNREFUSED`.
      Non-sockets and symlinks at the path are refused untouched. Drop removes
      the socket and releases the lock. 15 unit tests.)
- [x] **2.3 Peer credential check.** `SO_PEERCRED` on Linux, `getpeereid` on macOS;
      reject mismatched UID before parsing a request. Test with a helper that
      connects and asserts rejection when the check is forced to fail.
      (`PeerCredentials` + `peer_credentials()`, and
      `DaemonSocket::accept_peer()` rejects with `SocketError::PeerRejected`
      before reading; unsupported Unix targets fail closed. Linux pid is
      informational; macOS reports no pid.)
- [x] **2.4a Daemon core + `pmd` binary.** Reusable `src/daemon.rs` that holds the
      derived 32-byte vault key (not the decrypted vault), `mlock`s it,
      zeroizes it on drop, sets `prctl(PR_SET_DUMPABLE, 0)` and disables core
      dumps, installs SIGTERM/SIGINT handlers, and serves length-prefixed
      `ping`/`lock` requests over `accept_peer()` (length-prefixed responses too).
      `pmd` reads the key from stdin (never argv) and takes `--vault` and
      `--runtime-dir`. Tests: ping/lock round-trip, lock removes the socket and
      stops the process, SIGTERM and SIGINT exit cleanly and remove the socket,
      malformed/oversized messages are rejected without a crash, a wrong key
      does not start, a second instance is refused, `run` is refused for now,
      and the secret never appears in socket bytes or daemon stderr.
- [x] **2.4b `pm unlock` / `pm lock` CLI.** `unlock` is human-only (TTY on stdin
      and stdout, refused in agent context with exit 5), prompts once, derives
      and verifies the key, spawns `pmd` detached with the key over stdin, waits
      for readiness, then exits. `lock` sends the lock request and reports.
      Tests: non-TTY/agent refusal, unlock then lock end-to-end, no key or
      secret in argv/stdout/stderr.
- [x] **2.4c Idle timeout.** Default 15 minutes, configurable; daemon exits and
      wipes the key after inactivity, refreshed by successful requests. Test:
      short timeout exits, activity before the deadline keeps it alive.
      (`pmd --idle-timeout SECS`; `passmgr unlock --idle-timeout SECS`
      (also `=SECS`) passes it through. Activity = a request decoded after the
      peer check; malformed frames are answered but never refresh. Zero is
      refused. Not an authorization boundary until 2.5/3.1: any same-user
      process can `ping` to keep the daemon alive; documented in `daemon.rs`.)
- [x] **2.5 Session token file** (`$XDG_RUNTIME_DIR/passmgr/session`, 0600) written
      at unlock; requests carry it; mismatch rejected. Test: wrong token rejected,
      token file mode is 0600. (Token is 32 random bytes as 64 lowercase hex
      chars; protocol bumped to version 2 with a required `token` envelope
      field; `unauthorized` is a distinct response and does not refresh the
      idle timer. `lock` and a daemon exit remove the file. Clients refuse a
      token file that is not a regular 0600 file owned by the user.)
- [x] **2.6 `run --env NAME=<ref> -- <cmd>` via the daemon.** Split into ordered
      pieces because the item spans the redactor, the wire protocol, the daemon
      and the CLI. (All pieces landed: 2.6a–2.6d.)
- [x] **2.6a Streaming redactor (`src/redact.rs`).** Pure, reusable byte-stream
      redactor: replaces every occurrence of the injected value with a fixed
      marker and holds back a partial-match suffix so a value split across two
      reads is still caught. Bounded pending buffer, zeroized on drop, redacted
      `Debug`. Tests: whole and repeated occurrences, a split at every byte
      offset, byte-at-a-time input, overlapping occurrences, binary bytes, an
      empty value, `finish` flushing a trailing partial prefix, the pending
      bound, and no secret bytes in `Debug`. (If the default `[REDACTED]`
      marker would itself contain the value, a run of a byte absent from the
      value is used instead. Best-effort: a hostile child that holds the value
      can still exfiltrate it by other channels.)
- [x] **2.6b Protocol streaming `run` responses.** `stdout`, `stderr` and `exit`
      frames with hex-encoded data (arbitrary bytes survive JSON), plus stable
      failure codes (`not_found`, `spawn_failed`). Tests: round-trip of binary
      payloads, chunk-size cap, unknown frame types rejected without panic.
      (`RunFrame` is separate from `Response`; 16 KiB raw chunk cap; `exit`
      carries `code` xor `signal`; protocol stays v2; response code moved to
      `src/protocol/response.rs`.)
- [x] **2.6c Daemon executes `run`.** Decrypt, resolve the `pm://` ref, spawn the
      child with only the requested variable injected, stream redacted
      stdout/stderr, return its exit code. Tests: child sees the variable; the
      value appears in neither socket bytes nor daemon output; missing ref and
      failed spawn are distinct non-fatal errors; streaming output larger than
      one chunk is redacted across chunk boundaries. (`src/runner.rs` owns the
      spawn/redact/relay loop; the daemon refuses loader/shell-hook variable
      names and starts the child from a fixed env allowlist, not the daemon's
      environment. **Transitional:** `run` is authorized by the session token
      until TODO 3.6 adds grants.)
- [x] **2.6d CLI `run` + client reader.** `passmgr run --env NAME=<ref> -- <cmd>`
      forwards frames to its own stdout/stderr and exits with the child's status;
      refuses malformed specs and non-daemon operation with stable exit codes.
      Tests: end-to-end injection, output relay, redaction, exit-code
      propagation, and agent-mode use (this is the intended agent surface).
      Audit-log assertions belong to 3.3, when the log exists.
      (Exactly one `--env` per run because the protocol injects one value;
      signal N renders as 128+N. Reader is `client::run`; e2e in `tests/run.rs`.)
- [x] **2.7 `SECURITY.md` limit note**: same-user process can read
      `/proc/<pid>/environ` while the child runs. Not optional. (Created
      `SECURITY.md` with the accepted limits, interpreter exfiltration,
      output-only redaction, and the transitional session-token disclosure;
      pinned by `tests/docs.rs`.)

## Phase R — review findings (fix first)

Findings from the security review of `49d9915..3500f6d` (details in
`PROGRESS.md`). Each item names the code, a failure that reproduces today, and
the test that must fail before the fix and pass after it. They come before
Phase 3: R.1 breaks a containment guarantee that the design already claims.

- [x] **R.1 A long-running `run` defeats `lock`, the idle timeout and SIGTERM.**
      `src/daemon.rs:383-397` accepts and serves one connection at a time, and
      `src/daemon.rs:452`/`:481` (`serve_run`) calls `runner::execute`
      synchronously, so a second connection (`passmgr lock`) is never read.
      When the child closes stdout/stderr, `src/runner.rs:199` takes
      `Relay::Finished` and `src/runner.rs:202` calls `child.wait()` without
      polling the cancel flag, so the daemon's SIGTERM handler is not
      observed either. Failure: `passmgr run --env K=pm://… -- sh -c 'exec
      >/dev/null 2>&1; sleep 1h'`; `passmgr lock` exits 1 after its 5 s read
      timeout, `pmd` stays alive after SIGTERM (reproduced: alive 2 s later),
      and the idle-timeout check at `src/daemon.rs:379` is never reached, so
      the vault key and the child's copy of the secret stay usable for the
      whole hour. This contradicts `DECISIONS.md:244-246` ("lock, SIGTERM,
      SIGINT and the idle timeout all wipe the key") and `SECURITY.md`'s
      containment claims; `PROGRESS.md:105-108` recorded only the lock part
      and wrongly says SIGTERM stops the run.
      Fix direction: serve `Run` on a worker thread (or otherwise keep the
      accept loop responsive to `Lock`/`Ping`), make `lock` cancel in-flight
      runs, and replace the blocking `wait()` in `Relay::Finished` with a
      `waitpid(WNOHANG)` loop that checks the cancel flag every 100 ms.
      Test: e2e `run` a child that closes both pipes and sleeps 30 s; assert
      `lock` returns `Locked` within 2 s and the child is reaped, that SIGTERM
      terminates `pmd` within 2 s, and that a 1 s idle timeout shuts the
      daemon down (killing the child) while the run is still live.
      Done: `Run` is served on a scoped worker thread and the accept loop stays
      responsive; `lock`, a signal and the idle timeout set a shared cancel flag
      that kills and reaps the child (the `Relay::Finished` path polls
      `try_wait` every 100 ms). The idle-timeout e2e test uses 2 s, not 1 s, so
      it is not timing-sensitive; it still proves the child is killed.
- [x] **R.2 `run` resolves the command in `pmd`'s cwd and `PATH`, not the
      caller's.** `src/runner.rs:158-159` builds `Command::new(program)` and
      `command.args(&argv[1..])` with no `current_dir`, `src/cli/run.rs` sends
      no cwd, and `pmd` inherits the cwd of the terminal that ran `passmgr
      unlock` (`detach_session`, `src/daemon.rs:313-317`, only calls
      `setsid`). Failure (reproduced): the human unlocks from `~/work`; an
      agent in a repository with its own `./deploy.sh` runs `passmgr run
      --env TOKEN=pm://… -- ./deploy.sh` and the daemon executes
      `~/work/deploy.sh` with the secret in its environment. Relative
      arguments have the same problem, so the agent can hand the credential
      to a different script than the one it named. `PATH` lookup also uses
      the unlock shell's `PATH`.
      Fix direction: resolve the program and relative arguments against the
      caller's cwd (add the cwd to `RunRequest` and set `current_dir`, or
      canonicalize/refuse relative paths client-side), use a fixed child
      `PATH` or refuse `PATH` lookups, and document the choice in
      `DECISIONS.md`.
      Test: daemon cwd A, CLI cwd B, both containing `rel.sh`; assert the run
      executes B's script or is refused before spawn, never A's; add a unit
      test for a relative `command[0]`.
      Done: `RunRequest.cwd` (protocol v3) and `command[0]` must be absolute;
      the CLI resolves the program against its own cwd/`PATH` and the daemon
      runs the child with `current_dir`. A bare name that cannot be resolved
      is a usage error (exit 2); an absolute nonexistent path still reaches
      the daemon and fails as `spawn_failed` (exit 1). E2E tests cover both the
      cwd and the `PATH` split; `tests/daemon.rs` now runs in `/`.
- [x] **R.3 README and `--help` promise encoded-secret redaction that does
      not exist.** `README.md:173-174` says stdout/stderr are relayed with
      "the secret (and common encodings)" replaced by `[REDACTED]`, and
      `src/cli/help.rs:73` (fixture `tests/fixtures/help.txt:68`) repeats it,
      but `src/redact.rs` matches the exact secret bytes only;
      `SECURITY.md:108` correctly says encodings are not followed and belong
      to TODO 4.6. Failure: an agent runs `passmgr run --env K=pm://… -- sh
      -c 'printf %s "$K" | base64'`; the base64 value reaches the agent
      verbatim while the human-visible docs promised redaction. A hex-dumped
      credential leaked this way defeats the "agents never see plaintext"
      invariant without any warning.
      Test: implement TODO 4.6 first, or change README/`--help` to say that
      only the exact secret bytes are redacted; add a `tests/docs.rs`
      contract that README, `--help` and `SECURITY.md` agree on that limit,
      and an e2e test with a base64-encoded secret showing the documented
      behavior.
      Done: took the documentation branch. `README.md`, `src/cli/help.rs` and
      `tests/fixtures/help.txt` now say an **exact, contiguous occurrence** of
      the secret is replaced, and that encoded or transformed copies (base64,
      hex, percent-encoding, case changes) are not; README cites `SECURITY.md`
      limit 3. `tests/docs.rs` runs the real `passmgr --help` and pins the
      agreement of all three documents (and the absence of the old "common
      encodings" promise). `tests/run.rs` proves the documented behavior with
      a canary and its base64: the raw value is redacted, the encoded copy is
      relayed verbatim. No code changed; 4.6 still owns the fix.
- [x] **R.4 `--db`/`PASSMGR_DB` are documented as global but silently
      ignored by `run`.** `src/cli/help.rs:89` lists `--db PATH` under
      "Global options" and `README.md:47`/`:53` show it, but
      `src/cli/mod.rs:81` dispatches `Command::Run` without the parsed path
      (`RunOptions` in `src/cli/args.rs` has no db field), so `run` always
      talks to whichever daemon owns the runtime socket. Failure: `passmgr
      --db ~/vaults/work.dat run …` against a daemon started for
      `~/personal.dat` reports `not_found` for a valid ref, or (when the two
      vaults are copies) injects the other vault's password while the human
      believes the `--db` vault was used.
      Fix direction: either reject `--db`/`PASSMGR_DB` for `run` with exit 2
      before connecting (and say so in `--help`), or make the run request
      name/verify the vault the daemon serves; record the decision.
      Test: with two vaults, assert the chosen behavior: a clear usage error,
      or that the ref is resolved in the `--db` vault; add the `tests/docs.rs`
      contract.
      Done: took the refusal branch. `parse_args` rejects `run` with `--db`
      or a non-empty `PASSMGR_DB` (exit 2) before resolving the program or
      contacting the daemon; the message names the variable and says `run`
      uses the daemon's vault. `--help`, the golden fixture and README state
      the rule; `tests/docs.rs` pins it. E2E proves the child never runs and
      the refusal contains no secret.
- [x] **R.5 The SECURITY.md disclosure test can pass without the
      disclosure.** `tests/docs.rs:29` asserts `SECURITY.contains("same
      user")`, but the first matching sentence is `SECURITY.md:16` ("a process
      running as the same user can read the 0600 session file"), not the
      accepted-limit sentence at `SECURITY.md:71` about
      `/proc/<pid>/environ`. Failure: deleting or rewording limit 1 still
      leaves the test green, so the next iteration can silently drop the one
      document that admits the injected-child exposure.
      Test: assert on a stable, specific phrase from the limit itself (e.g.
      `/proc/<pid>/environ` plus `same user`), and use the same style of
      contract for the R.3 and R.4 claims so a doc edit cannot regress them.
      Done: `tests/docs.rs` gained `markdown_limit`/`security_limit`, which
      scope a contract to one `### N.` limit; a missing limit is a hard
      failure. `security_documents_the_proc_environ_limit` now requires three
      contiguous phrases from limit 1, so the session-file sentence at
      `SECURITY.md:16` cannot satisfy it. `limit_contracts_reject_the_
      phrase_from_another_section` proves the same phrase outside limit 1 is
      rejected, and the limit 3 contracts (sandbox, encodings) are scoped the
      same way. Verified by rewording limit 1: the test fails.
